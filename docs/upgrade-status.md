# Web upgrade verification

## Implemented

- Shared navy/blue theme, consistent surfaces and controls, focus outlines, reduced-motion support.
- Password visibility toggle and registration password guidance.
- Offline notice that updates on connection changes.
- Read request timeout: 30 seconds; write request timeout: 120 seconds.
- Identical concurrent evaluation requests share one network submission. No automatic write retries.
- Existing local draft recovery and explicit retry flows remain intact.
- Result comparison against the preceding saved attempt of the same test type.
- Mobile profile-grid and analytics-column overflow fixes.
- Sample-data, non-interactive signed-in previews generated by `PPDT_UI_SNAPSHOTS=1` when running app tests. Previews are ignored by Git and must not be deployed.

## Verification scope

The 11 preview routes (dashboard, practice, history, analytics, guide, profile, and all five test setup screens) were checked for horizontal overflow at 390, 820, and 1280 pixels. These previews use mocked account data; they do not validate live authentication or submissions. Automated tests cover interactive practice flows and result rendering.

## Requires approved content or backend work

- Password reset: the current backend has no reset-request/reset-completion endpoints. Requires a provider-backed reset flow and configured recovery redirect; do not send credentials or tokens through query parameters/logs.
- Terms and privacy: the inline notice is a short product notice, not an approved comprehensive policy. The product owner must supply approved text, policy versions, and effective dates.
- Acceptance audit: the live backend stores research consent but has no terms-version acceptance contract. Add server-side acceptance validation and storage after policies are approved. A browser checkbox alone is not a server-side audit record.
- Durable idempotency: frontend coalescing prevents concurrent duplicate clicks in one tab. It cannot prove whether a timed-out request saved server-side, or prevent duplicates across tabs/restarts. Requires a server-side idempotency key and durable result lookup before automatic retry is safe.

No live practice attempts were submitted, no account was created, and no backend deployment was performed during these checks.
